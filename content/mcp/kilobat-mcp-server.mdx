## Content

Kilobat exposes measurements from the local Mac through `kilobat mcp`, a stdio
MCP server included in its open-source CLI. Use it when a coding agent needs
evidence about the machine where a request is failing: Wi-Fi quality, the router,
DNS, a host’s connection path or whether the connection is metered.

A hosted server on another machine cannot measure this Mac’s local Wi-Fi link.
Kilobat’s local process is the useful part of this integration. It also exposes
settings-changing tools; this is not a monitoring-only server or a security
sandbox.

## Install and Configure

Install the CLI from its canonical Homebrew tap:

```bash
brew install seifip/kilobat/kilobat
kilobat --version
```

The tap builds from source and requires macOS 14+ and Xcode 16+. For a manual
build, follow the public repository’s Swift 6 instructions. The source and tap
reviewed for this entry point to v0.20.0.

Register the server with Claude Code:

```bash
claude mcp add kilobat -- kilobat mcp
```

For a client configured through JSON, use the `mcpServers` block above. This is a
local command, not a hosted HTTP endpoint. If a GUI client cannot find `kilobat`,
use the absolute executable path from `command -v kilobat` in that client’s
configuration. Restart or reload the client as its documentation requires, then
check that the server connects and exposes its tools.

## Use Cases

- For one API or website that will not connect, call `diagnose_connection` with
  the failing URL as `target`. Read its measured layers and skipped checks before
  attributing a cause. A successful fresh probe does not prove a separate app’s
  existing connection is healthy.
- For a generally slow connection, start with `diagnose_network`, then use
  `get_status` to identify other apps using bandwidth. Missing Wi-Fi names can
  reflect Location permission, rather than absence of a wireless network.
- Before a large download, use `get_conditions` to inspect metered-link and
  machine conditions. A speed test itself uses data, so it is not a free check
  on a capped hotspot.

## Permissions and Limits

The CLI and public MCP implementation are GPL-3.0-only. The desktop app is a
separate proprietary product. Network names require the running app with
Location permission; persisted history comes from app recording, and filtering
requires the app’s enabled network filter. Saving a rule is not evidence that
traffic was blocked.

The MCP instructions ask the model to obtain approval before changes. In the
reviewed v0.20.0 dispatcher, a validated tool call proceeds to its handler
without a common human-approval check. A client policy, individual handler or
macOS prompt may add controls, but the instructions alone do not enforce them.
Do not enable unattended writes on the assumption that this server prevents
them.

Tool output can enter the agent’s conversation and provider logs. Keep private
network identifiers out of shared reports. Local transport does not prevent the
diagnostic targets, package registries or public-IP service from receiving the
requests made to them.

## Verification

Source and installation metadata were reviewed on 1 November 2026. The released
v0.20.0 source was built on a Mac. Direct stdio initialization, tool discovery
and a `diagnose_connection` call against `example.com` succeeded in the local
check. A separate `kilobat diagnose --json` check returned valid JSON with exit
status 0. No settings-changing tools were exercised.
