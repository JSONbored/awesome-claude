## Content

Apple Docs 2.0 MCP is a third-party MCP server that lets Claude answer from
Apple's own developer documentation instead of memory. Its search returns the
results developer.apple.com shows: API reference, articles, sample code, the
Human Interface Guidelines, App Store Connect Help and WWDC videos. Pages come
through whole, with every member's full signature, what a type inherits from
and conforms to, related APIs and the OS versions that support it.

Use it before writing or fixing Swift or any code that calls an Apple framework,
for Human Interface Guidelines questions, and to find WWDC session code for an
API. An offline index of 336,629 pages finds a page by its name or part of one,
and 1,700 WWDC sessions (2014–2026) ship with the package, 1,416 with
transcripts and 715 with code.

## Features

- Search Apple developer documentation with developer.apple.com's own results.
- Read whole documentation pages with full signatures, inheritance, conformances, related APIs and OS availability.
- Find any of 336,629 pages by name or part of one in an offline index: symbols, articles, sample code, Info.plist and entitlement keys, web-service endpoints, Human Interface Guidelines and App Store Connect Help pages.
- Read the Human Interface Guidelines, tutorials, App Store Connect Help and App Store Connect API endpoints.
- Search framework symbols, related and similar APIs, platform compatibility, sample code, documentation updates and technology overviews.
- Browse and search 1,700 WWDC sessions (2014–2026) offline, with transcripts and timestamped code.
- Run as a stdio MCP server through `npx`, with no API key or account.

## Installation

Add the server to Claude Code:

```bash
claude mcp add apple-docs -- npx -y apple-docs-2.0-mcp
```

For JSON-based MCP clients such as Claude Desktop, use:

```json
{
  "mcpServers": {
    "apple-docs": {
      "command": "npx",
      "args": ["-y", "apple-docs-2.0-mcp"]
    }
  }
}
```

Restart the MCP client after adding the server.

## Use Cases

- Ask Claude to look up an API in Apple's docs before it writes SwiftUI or UIKit code.
- Open a page directly from a type, method or Info.plist key seen in code or an error message.
- Check which OS versions support an API before using it.
- Read the Human Interface Guidelines page for a component before designing it.
- Find WWDC session code that uses an API, then read the session.
- Look up App Store Connect Help or an App Store Connect API endpoint.

## Safety and Privacy

The server only reads public Apple documentation and its bundled data, but
prompts can still carry private development context. Keep proprietary code,
unreleased app plans, internal project names and private bundle identifiers out
of documentation queries unless that disclosure is approved.

Documentation changes, and beta or deprecated APIs need extra care. Verify
compatibility-sensitive guidance against the live Apple documentation before
shipping platform code.
