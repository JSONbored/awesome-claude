## Overview

The **Blawgy MCP Server** is the hosted Model Context Protocol server for [Blawgy](https://blawgy.com),
an SEO blog service that researches keywords, writes articles with images and internal links, and
publishes them to WordPress, Shopify, Webflow, Wix, Framer, Ghost and Duda on a schedule. The MCP
server gives Claude everything the dashboard can do: read Google Search Console traffic, rankings
and indexing status, run keyword research, build and reorder the content plan, write and edit
articles, draft and approve refreshes of live posts, and manage images, products, location pages,
guardrails, settings, webhooks and your team.

The server runs at `https://app.blawgy.com/mcp` over Streamable HTTP. Authenticate with OAuth 2.1
(PKCE and dynamic client registration) or an API key sent as a bearer token. The listing
repository on GitHub holds the README, `server.json` and logo under MIT; the server itself is part
of the Blawgy service and is not open source. MCP access is included on every paid plan.

## Key capabilities

- **Keyword research**: find keywords by difficulty and intent and add the best ones to the plan.
- **Search Console**: read traffic, rankings and indexing status for published posts.
- **Content plan**: add keywords, move dates, pause or resume autopilot, set posts per week, reschedule overdue entries.
- **Articles**: write now, edit, reschedule, preview, publish CMS drafts, republish, delete.
- **Article builder**: titles, outline, section-by-section writing, remix from URLs.
- **Smart updates**: draft and approve refreshes of live posts that are losing clicks.
- **Images, products and location pages**: manage the photo bank, product catalog and local pages.
- **Settings and integrations**: guardrails, webhooks, CMS connections and team invitations.

Slow work such as research, writing, scans and syncs returns a job id immediately and a status
tool reports progress. Every site tool takes a `site` argument (the domain).

## Installation

### Claude Code (remote, OAuth)

```bash
claude mcp add --transport http blawgy https://app.blawgy.com/mcp
claude mcp login blawgy
```

You can also run `/mcp` inside a session to sign in. On first use Claude Code opens a browser
window for Blawgy OAuth, where you pick the sites and whether the connection can write.

### Claude Code (remote, API key)

```bash
claude mcp add --transport http blawgy https://app.blawgy.com/mcp \
  --header "Authorization: Bearer blk_live_..."
```

### Project `.mcp.json` (shared with your repo)

```json
{
  "mcpServers": {
    "blawgy": {
      "type": "http",
      "url": "https://app.blawgy.com/mcp",
      "headers": { "Authorization": "Bearer ${BLAWGY_API_KEY}" }
    }
  }
}
```

### Claude.ai and Claude Desktop (connector)

Open Customize, then Connectors, then Add custom connector. Name it Blawgy, paste
`https://app.blawgy.com/mcp`, press Connect and sign in with your Blawgy account. To use an API
key instead, add `Authorization` with `Bearer <key>` under Request headers.

### Other clients

Gemini CLI: `gemini mcp add --transport http blawgy https://app.blawgy.com/mcp`. Clients that only
support stdio can bridge with `npx -y mcp-remote https://app.blawgy.com/mcp`. Cursor, VS Code,
Windsurf, Codex CLI and Cline instructions are in the listing repository README.

## Requirements

- A Blawgy account on a paid plan or free trial with at least one connected site.
- An MCP client with remote Streamable HTTP support (Claude Code, Claude Desktop, Claude.ai connectors, Cursor, Gemini CLI, Codex CLI).
- OAuth sign-in, or an API key created under Settings, AI agents.

## Security

- Credentials are scoped to one site, all your sites, or (for partners) every approved client site, and are read only or read and write. Read-only credentials never see write tools.
- Delete, publish, revert, disconnect and cancel require the agent to confirm with a one-line description of exactly what will happen.
- Keys and tokens are stored as hashes, shown once at creation, and can be revoked at any time with effect on the next call.
- Every call is logged with the tool, the site, the result and the time. Argument values are not stored.
- Agents never get admin access. Billing and account deletion stay in the browser.
- OAuth metadata is published at `https://app.blawgy.com/.well-known/oauth-authorization-server` and `https://app.blawgy.com/.well-known/oauth-protected-resource`.
