## What it does

Openhook gives a running agent a place to receive an external callback. The agent
creates an inbox, passes its public address to a sender, waits for an event, and
checks what arrived before continuing. HTTP, SMTP, and authoritative DNS capture
are implemented by the server; email and DNS require additional deployment setup.

This entry covers the free, MIT-licensed server. The local HTTP setup below does
not require an Openhook account, subscription, or provider API key.

## Installation

Review the source, then run the install commands above. Keep that terminal open.
The web interface is at `http://127.0.0.1:8788/app` and the Streamable HTTP MCP
endpoint is at `http://127.0.0.1:8788/mcp`.

In another terminal, run the `claude mcp add` command above and check the connection
with `claude mcp list`. The JSON snippet is an alternative project configuration;
merge it into existing settings rather than overwriting other MCP servers.

For external callbacks, follow the project's
[deployment guide](https://github.com/openhook-dev/openhook-inbox/blob/main/docs/deployment.md).
A sender on the internet cannot reach your loopback address. The repository also
supports stdio, but a separate HTTP process sharing the same database must remain
running to receive HTTP callbacks.

## Usage

1. Call `create_webhook` for a disposable inbox. Store the returned private token
   with the task and give only the returned public URL to the callback sender.
2. Send a synthetic event from the local system you are testing.
3. Call `wait_for_request` with the private `webhook_token`, `since: 0`, and a
   bounded `timeout_seconds`. Using zero includes callbacks received before the
   wait began.
4. Check the event's source and content. Use `get_request` when list previews are
   insufficient; deduplicate by event ID and save `next_since` after processing.
5. Unregister any provider subscription created for the test, then delete the
   disposable inbox with `delete_webhook`.

A timeout means no matching event arrived during the wait. It does not establish
completion. MCP waiting returns to an active client; it does not restart a stopped
agent session. A captured callback proves receipt at Openhook, not successful
processing by your application's handler.

## Verification

With the local HTTP server still running, run this from the source checkout:

```sh
python3 examples/first_callback.py --url http://127.0.0.1:8788
```

The example creates a disposable inbox, sends a synthetic callback, compares its
original bytes, and deletes the inbox. The private token stays in memory.

The maintainers verified live MCP discovery of 29 tools and a separate synthetic
HTTP callback through MCP, including exact-body comparison and cleanup on
2026-10-16. Claude Code plugin installation and server connection have also been
checked. These checks are not a model-driven end-to-end evaluation or an
independent security audit.
