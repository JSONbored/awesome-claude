## Overview

Open Agent API gives existing apps and SDK clients a callable API for agents you already run. The `oaa mcp` bridge is a local stdio process and does not turn the project's public website into a remote MCP endpoint.

## Setup

1. Install Open Agent API from its [source or a tagged release](https://github.com/jiangxingfan1-coder/Open-Agent-API/blob/main/docs/install.md). Run `oaa quickstart` to create a loopback gateway and publish the offline `agent/sample`.
2. Have the gateway operator issue a scoped key using [the gateway's key endpoint](https://github.com/jiangxingfan1-coder/Open-Agent-API/blob/main/docs/deploy-public.md#7-distribute-caller-keys). For a first trial, use `{"name":"claude-reader","agents":["agent/sample"],"scopes":["read"]}` and save only the resulting caller key in a private file outside the project.
3. Replace the example path in the install command and run it in the project that should use the bridge. This uses Claude Code's local scope. Check the connection with `claude mcp list`.

## What To Expect

`oaa_list_agents` can discover the offline sample with a reader key. `oaa_invoke` needs the separate `invoke` scope. Starting the bridge does not authorize execution or approval. The project also publishes its own [v0.0.64 MCPB bundle and checksums](https://github.com/jiangxingfan1-coder/Open-Agent-API/releases/tag/mcp-open-agent-api-v0.0.64); this entry does not request a HeyClaude download mirror.

The registration was tested with Claude Code 2.1.330 and Open Agent API v0.0.64 on macOS arm64. The configured bridge connected; a missing key file did not. These connection checks sent no chat prompt and created no additional gateway runs.
