## Content

i2v.ai runs one API for both image and video generation: 12 image models and 16 video models behind the same request shape, covering text-to-image, text-to-video and image-to-video. The official MCP server exposes that API to Claude so a conversation can list what is available, get the parameters for one model, quote the price of a specific job in USD, then submit and poll the task.

The distinguishing behaviour is that pricing comes first. `estimate_cost` returns the USD price for a concrete task, and `create_task` accepts a `maxCostUsd` ceiling that the server enforces before any balance is frozen. A generation run that would cost more than the ceiling is rejected up front instead of being charged.

## Features

- `list_models` enumerates the currently available image and video models with their capabilities.
- `get_model_params` returns the accepted parameters, defaults, and constraints for one model.
- `estimate_cost` quotes a concrete task in USD without spending anything.
- `create_task` submits a generation task and honours a caller-set `maxCostUsd` ceiling.
- `get_task` polls status and returns the resulting asset URLs once a task finishes.
- `list_prices`, `get_account` and `get_usage` report the catalogue, balance and consumption.
- `create_upload_url` and `complete_upload` stage your own reference media for image-to-video.
- `search_docs` reads the i2v.ai documentation from inside the session.

## Use Cases

- Price a video concept before committing to it: quote three models, pick one, then submit with a ceiling.
- Generate a product still and animate it through an image-to-video model in the same conversation.
- Batch several short clips while holding each task to a fixed USD maximum.
- Let an agent decide to decline a job when the quote exceeds the budget it was given.

## Installation

### Claude Code (hosted endpoint)

```bash
claude mcp add --transport http "i2v" https://i2v.ai/api/mcp
```

Claude Code performs the OAuth 2.1 authorization-code flow with PKCE and dynamic client registration on first use. The requested scopes are `mcp:read` for reads and quotes, and `mcp:write` for uploads and task submission.

### Claude Desktop (hosted endpoint)

Add the HTTP server to your MCP configuration:

```json
{
  "mcpServers": {
    "i2v": {
      "type": "http",
      "url": "https://i2v.ai/api/mcp"
    }
  }
}
```

### Local stdio server

The same tools also run locally over stdio, which is useful when the client cannot do remote OAuth or when you would rather authenticate with an API key:

```bash
claude mcp add i2v-local -- npx -y @i2v-ai/cli mcp
```

Set `I2V_API_KEY` in the environment that starts the server. Without a valid key the server answers the MCP `initialize` request with an `unauthorized` error, which is the expected behaviour rather than a crash.

## Requirements

- An i2v.ai account. Keys are created at https://i2v.ai/me?section=api-keys.
- A positive USD balance for generation. Reads, model metadata and quotes are free.
- A client with Streamable HTTP support for the hosted endpoint, or Node.js 20+ for the stdio package.

## Security

- Generation spends balance. Send `maxCostUsd` with every `create_task` call and treat the quote as advisory until the task is submitted.
- Consent to the smallest scope you need: an agent that only explores the catalogue needs just `mcp:read`.
- Prefer the API key route with a per-key USD limit and, optionally, an IP allowlist when the client cannot manage OAuth tokens.
- Uploaded files land in private object storage and are served through signed URLs.
