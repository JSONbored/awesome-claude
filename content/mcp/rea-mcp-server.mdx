## What It Does

REA exposes local reverse-engineering workflows through a stdio MCP server and
CLI. It helps agents inspect shipped binaries and JavaScript/Electron packages
while preserving artifact identity, source locations, observations, inferences,
and explicit unknowns. Use the available evidence to answer a concrete question
rather than treating a model's explanation as proof of runtime behavior.

Deep native analysis uses separately installed Hopper, Ghidra, or IDA. Provider
and host coverage differ. Static JavaScript analysis does not require those
native engines. Setup and selected runtime/annotation operations can have effects;
this server is not entirely read-only.

## Configure and Use

The configuration above launches the pinned published package over stdio. It
requires Node.js/npm and a client that permits a local child process. Follow the
upstream installation guide for client-specific configuration, native provider
prerequisites, and REA doctor/setup workflows. A saved config alone does not prove
that the client connected.

For an extracted Electron application, ask the connected agent to call
`analyze_javascript_application` with its absolute path and identify the modules
and IPC handlers implementing a particular feature. Inspect returned source
locations, artifact identity, limitations, and unknowns before drawing conclusions.

The optional [reverse-engineer-anything skill](https://github.com/morluto/rea/tree/main/.agents/skills/reverse-engineer-anything)
provides routing and evidence-handling instructions, plus five local reference
guides. Installing those instructions does not install REA, configure MCP, or
provide native decompilers. It excludes ordinary complete-source architecture
analysis and can use the CLI when MCP is unavailable.

## Verification Scope

The published rea-agents@6.1.0 stdio server was connected to an MCP SDK client and
`analyze_javascript_application` successfully analyzed a local Electron fixture.
The same package's CLI returned artifact identity, module/import information,
IPC observations, and limitations. These checks establish the JavaScript workflow
and stdio transport, not a new Claude-host or native-provider verification.

The companion skill was discoverable with skills@1.7.1. An isolated Cursor-targeted
installation copied SKILL.md and all five reference guides. That checks installation,
not automatic activation or a Cursor host task. Capabilities in newer repository-main
instructions should be checked against the installed server's actual catalog.
