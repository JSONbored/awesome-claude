## What this collection sets up

This collection turns documentation into a repeatable Claude Code workflow:
capture project context, draft or update docs, check coverage, validate links,
generate API references, and connect published documentation systems. It is
useful for teams that want Claude to help maintain docs without treating
generated prose as automatically publishable truth.

## Layers

### 1. Project context and writing ownership

- **claudemd-builder** creates or refreshes CLAUDE.md context so future doc
  generation follows local conventions.
- **technical-documentation-writer-agent** gives the workflow a focused writing
  role for API, feature, onboarding, and architecture documentation.

### 2. Drafting and local generation

- **docs** provides an explicit command path for documentation generation.
- **documentation-generator** and
  **documentation-auto-generator-on-stop** support generated or updated docs
  during coding sessions.
- **api-endpoint-documentation-generator** helps turn endpoint changes into API
  reference material.

### 3. Quality gates

- **documentation-coverage-checker** highlights undocumented functions,
  modules, components, or endpoints.
- **markdown-link-checker** validates internal and external documentation links
  before review.

### 4. Publishing and published-doc retrieval

- **mintlify-documentation-automation** and **mintlify-docs** support Mintlify
  docs maintenance and publishing workflows.
- **gitbook-published-docs-mcp-server** lets Claude retrieve published GitBook
  documentation when a team needs to compare generated drafts with the live
  public docs.

## Suggested order

Start by building CLAUDE.md context, then add the documentation writer agent and
manual docs command. Enable generation hooks after the file scope is understood.
Add coverage and link checks before publishing tools. Connect Mintlify or GitBook
last, after the team has agreed which docs are safe to publish or query.
