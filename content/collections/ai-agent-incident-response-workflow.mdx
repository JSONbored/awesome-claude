## What this collection sets up

This workflow is for diagnosing production AI agent incidents where failures
span prompts, tools, traces, user-facing sessions, logs, and backend
dependencies. It is narrower than a general debugging toolkit: the focus is
incident triage for agent systems with observable evidence and privacy-aware
artifact handling.

## Layers

### 1. Telemetry and triage model

- **ai-agent-observability-incident-response** defines the telemetry contract,
  SLOs, alert thresholds, and runbook shape for agent incidents.
- **production-reliability-engineer** keeps the response aligned to severity,
  mitigation, rollback, and post-incident review practices.

### 2. Incident context from production systems

- **sentry-mcp-server** brings issue, stack trace, and release context into the
  investigation.
- **grafana-mcp-server** connects dashboards, metrics, logs, and traces for
  correlated observability.
- **jam-mcp-server** adds user reproduction evidence and browser/session
  artifacts when the incident starts from a reported UI failure.

### 3. Timeline and dependency analysis

- **log-parsing-incident-timeline** turns logs into chronological incident
  timelines with error grouping and correlation.
- **database-query-performance-logger** adds database latency and query-level
  evidence for agent workflows that depend on retrieval, memory, billing, or
  stateful backend operations.
- **debugging-assistant-agent** supports targeted root-cause investigation once
  evidence has been collected.

## Suggested order

Start with the observability skill and reliability agent so the incident
response contract is clear. Connect Sentry and Grafana next, then add Jam for
user reproduction evidence. Add log timeline parsing and database performance
logging after access boundaries and redaction rules are understood.
