## Editorial notes

OrcaReplay is for the question a coding agent cannot answer well from memory: what did the last run actually do, and can that failure be made to happen again. It launches the agent as a child process with the provider origin redirected for that process only — nothing is installed into the agent — and stores the verbatim request and response bytes along with tool calls, shell exit codes and file changes. `orca replay` then serves the recording back, so the agent re-executes its own control flow and tool dispatch while the model's answers come from the trace.

The practical fit for Claude Code users is twofold. A session that went wrong becomes something a colleague or a maintainer can reproduce without your API key and without spending tokens, which turns a bug report into a runnable artifact. And the same recording runs in CI as a regression test at no cost, which is otherwise impractical for anything involving a model. It ships an MCP server and an agent skill so Claude Code can read its own past runs instead of reconstructing them.

Adapters are verified hands-on for Claude Code, Codex, Cursor, goose, opencode, Kilo, Qwen Code and OpenClaw, plus framework agents through a generic OpenAI-compatible mode. Two limits are worth knowing before relying on it: a matching replay shows the recorded run reproduces, not that a fresh run would fail the same way (the model is not re-asked), and it is not an evaluation or observability platform — there are no metrics, judges or dashboards.
