## What AI Gateway Adds

AI Gateway gives agent operators a control point between application code and LLM
providers. That control point can surface request volume, provider behavior,
errors, caching, logs, and routing decisions before an experimental workflow
becomes a production cost problem.

## Setup Pattern

1. Create a gateway and pick a naming convention per environment.
2. Route one non-production agent through the gateway first.
3. Verify request logs, provider names, errors, and status codes.
4. Add cache or fallback behavior only after baseline visibility exists.
5. Track cost and latency by workflow, model, provider, and environment.
6. Decide what prompt or response logging is allowed before sending private data.

## Review Checklist

- Gateway URL is environment-specific.
- Provider keys are stored in secrets, not source files.
- Logs are access-controlled and retention is understood.
- Cost, error, and rate-limit signals are reviewed after load tests.
- The team knows which prompts/responses may be logged.

## Troubleshooting

### Requests bypass the gateway

Search code for direct provider base URLs and SDK defaults. Some clients require
an explicit base URL override per provider.

### Logs show too much content

Reduce logged payload detail, separate sensitive workloads, or disable prompt and
response logging where policy requires it.
