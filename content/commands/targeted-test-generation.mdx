The `/targeted-test-generation` command applies [Anthropic develop-tests guidance](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)
to add minimal coverage around a specific change.

## Usage

```
/targeted-test-generation <file-or-symbol>
```

Target a changed source file or exported symbol that needs new or updated tests.

## What it does

When you invoke this command, follow these steps:

1. **Inspect the change.** Read the diff for the target file and list public behavior that changed.
2. **Find conventions.** Locate adjacent tests in the repository and match framework, naming, and assertion style.
3. **Define cases.** Draft happy path, boundary, and failure cases tied to the change—not exhaustive unrelated coverage.
4. **Write minimal tests.** Propose new test blocks or files that compile with the project's runner and import paths.
5. **Avoid flakiness.** Prefer deterministic inputs, fake timers only when necessary, and no live network dependencies.
6. **Run locally.** Execute the narrowest test command (for example `pnpm test path/to/file.test.ts`) and report failures.
7. **Summarize gaps.** Note untested edge cases that need human judgment or integration coverage.

## Output format

- **Target:** file or symbol under test
- **Cases:** table of scenario, expected result, test name
- **Proposed tests:** code blocks ready to paste
- **Run command:** exact local test invocation
- **Remaining gaps:** manual follow-ups

## Requirements

- Project test runner installed and documented in repository scripts.
- Operator review before committing generated tests.
