# JGS SE Knowledge Packs

`jgsystemsconsulting/jgs-se-knowledge-packs` is a curated catalogue of 74
systems-engineering reference packs written as standard Agent Skills
(`SKILL.md`). Each pack turns an open body of knowledge - a public-domain
handbook, an open-licensed specification, or a regulator's guidance - into an
on-demand reference a coding agent can load mid-task and cite.

Use this listing when a coding agent needs vetted systems-engineering domain
grounding: requirements elicitation and EARS patterns, architecture trade-offs,
test strategy, safety assurance, data engineering, or operations practice.

## Knowledge Freshness

Pack content is reconstructed from specific source editions, recorded per pack
in `catalog.json` and `NOTICE` at v1.24.1. Upstream standards bodies revise
their documents; check the source edition listed for a pack before relying on
chapter-level detail, and consult the repo CHANGELOG for catalogue updates.

## Retrieval Sources

This listing is grounded in:

- The upstream repository README and `catalog.json` (74 pack entries).
- The per-pack `PACK.yaml` provenance records and `NOTICE` attributions.
- The skills.sh listing for the catalogue.

## Core Workflow

List the available packs:

```text
npx skills add jgsystemsconsulting/jgs-se-knowledge-packs -l
```

Install one pack or the whole catalogue:

```text
npx skills add jgsystemsconsulting/jgs-se-knowledge-packs --skill sebok
npx skills add jgsystemsconsulting/jgs-se-knowledge-packs --all
```

Restart the agent, then invoke a pack by slug (`/sebok systems of systems`) or
route an open question through the `/se <question>` orchestrator, which picks
one to four packs and answers with pack and chapter citations.

## Capability Scope

The catalogue spans systems-engineering domains from public sources:

| Domain | Example packs |
| --- | --- |
| Requirements and SE bodies of knowledge | `sebok`, `requirements-writing`, `mit-ocw-se` (planned) |
| NASA and DoD practice | `nasa-se-handbook`, `dau-se-guidebook`, `dodaf`, `mil-std-881f` |
| Safety and assurance | `mil-std-882`, `nasa-system-safety`, `nhtsa-vehicle`, `nrc-nuclear` |
| Security engineering | `nist-ssdf`, `nist-csf`, `nist-sse`, `nist-800-171` |
| Cost, schedule, and test | `gao-cost`, `gao-schedule`, `gao-tra`, `nasa-ceh` |
| Regulated domains | `eu-ai-act`, `fda-med-device`, `easa-rules`, `jsp-936` |

Signposts (citation-only entries, zero reproduced content) map paywalled
landscapes such as ISO/IEC/IEEE standards, ECSS, and automotive functional
safety to their open paths.

## Production Rules

- Treat pack chapters as reconstructed reference notes; verify exact standard
  wording against the upstream source before contractual or safety use.
- Keep per-pack attribution intact when redistributing; pack content carries
  each source's own licence, independent of the repo's MIT tooling licence.
- Prefer the `/se` orchestrator for broad questions; it cites the packs it
  used instead of answering from general model memory.

## Use Cases

- Draft requirements sections against EARS patterns and SEBoK quality
  guidance.
- Compare NASA, DoD, and FAA practice on risk acceptance, V&V, or review
  gates while writing process documents.
- Ground safety-assurance or cybersecurity arguments in MIL-STD-882E, NIST
  SSDF/CSF, or sector regulators rather than recollection.
