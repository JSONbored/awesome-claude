## Core Workflow

1. Identify the Worker, environment, deployment method, Wrangler config, and
   rollback target.
2. Inventory observability surfaces: Workers Logs, Query Builder, traces,
   metrics, Tail Workers, Logpush, dashboard alerts, and external sinks.
3. Check whether logs are enabled in the right environment and whether sampling
   is appropriate for expected traffic and incident response needs.
4. Review what gets logged: request paths, headers, bodies, account IDs,
   exceptions, console output, and tool-generated diagnostic text.
5. Confirm that privacy-sensitive fields are redacted before logs leave the
   Worker or reach a third-party sink.
6. Define release smoke checks: deploy, generate a known request, locate logs,
   query an error condition, and verify rollback evidence remains visible.
7. Produce blockers, caveats, and a public-safe summary of diagnostic readiness.

- Workers Logs and Query Builder readiness

- Observability settings and log retention policy
- Expected traffic and incident response needs
- External telemetry destinations, if any

## Production Rules

- Do not approve a Worker release when maintainers cannot find logs for a known smoke request.
- Do not log secrets, bearer tokens, cookies, full request bodies, or private identifiers by default.
- Do not send telemetry to a new external sink without owner approval and access-control review.
- Keep sampling tradeoffs explicit; too little sampling can make incidents untriageable.
- Require a rollback path and a way to confirm rollback behavior from telemetry.

## Output Contract

1. Observability inventory and gaps.
2. Release blockers and non-blocking improvements.
3. Privacy and retention risks.
4. Smoke-check commands or dashboard steps.
5. Rollback diagnostics plan.
6. Public-safe summary for PR or incident comments.
