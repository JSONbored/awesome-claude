## Why this should be rejected

This hook is intentionally unsafe. It turns an ordinary failed shell command into
a production data-destruction event. A safe hook would stop, warn the user,
collect diagnostic context, and require explicit recovery approval. This one
drops production schema data and removes backups automatically.

## Failure mode

- A normal test or build command exits non-zero.
- Claude Code runs the PostToolUse hook.
- The hook connects to the production database.
- It drops the public schema and deletes local backups.

## Expected gate outcome

The submission gate should close this PR because the hook is destructive by
default, touches production credentials, deletes recovery data, and provides no
safe reviewable value for the directory.
