## Safety Notes
- MCP servers can execute tools, read resources, and expose prompts; approve only trusted servers and review each tool boundary before use.
- Project-scoped .mcp.json changes affect collaborators after trust approval, so document server purpose, transport, and rollback steps.
- Remote MCP servers and OAuth flows can change account data depending on granted scopes; test with least-privilege credentials first.
## Privacy Notes
- MCP resources may expose local files, database metadata, ticket content, or third-party service data to Claude Code during retrieval.
- OAuth tokens and API keys must stay out of committed .mcp.json files, logs, screenshots, and shared transcripts.
- Server logs may retain prompts, tool inputs, resource identifiers, and error payloads; define retention and redaction before rollout.

## Core Workflow
1. Inventory every MCP server by name, scope, transport, command/URL, environment variables, and expected tools/resources.
2. Classify trust boundaries for local processes, project-shared configuration, remote endpoints, OAuth providers, and data stores.
3. Validate tool, prompt, and resource contracts with representative calls before approving broad access.
4. Reduce permissions to the minimum safe allowlist and record why each tool or server is approved.
5. Produce rollout, monitoring, incident response, and rollback instructions that a teammate can execute.

## Capability Scope
- Claude Code MCP server scope selection and conflict review
- Project `.mcp.json` readiness checks
- OAuth and secret-handling review
- MCP tool/resource/prompt contract validation
- Production rollout and rollback planning

## Production Rules
- Never approve an MCP server only because it starts successfully.
- Treat network-capable MCP servers as data-exfiltration paths until reviewed.
- Keep secrets in local environment or approved secret stores, not committed project files.
- Require a rollback path for every server, OAuth grant, and project-scoped config change.

## Troubleshooting
**Issue:** MCP tools are available but unsafe for shared use
**Fix:** move the server to local/user scope or deny risky tools until permissions are reviewed.

**Issue:** OAuth succeeds but tool calls fail
**Fix:** verify provider scopes, token storage, server logs, and Claude Code `/mcp` status before widening access.

**Issue:** Teammates see different MCP behavior
**Fix:** compare local, project, and user scopes, then document precedence and reset project approvals when needed.

## Output Contract
1. MCP readiness report with evidence and blocked items.
2. Exact config or command changes, with secrets redacted.
3. Permission and OAuth review table.
4. Validation commands or manual checks.
5. Rollback and incident-response plan.
